# 回想/回放台词截断成日文：根因与修复（v1.22，2026-11-21）

## 现象
剧情里一段「回想」重放了两句以前出现过的台词，**正文和回味（BACK LOG）都显示为日文且只有前半句**：

1. 原文 97 字节：`【ミツコ】「女っていうのはね、小さい頃の約束とかそういうの、ちゃあんと憶えているものなのよ？」`
   显示为前 **68** 字节：`【ミツコ】「女っていうのはね、小さい頃の約束とかそういうの、ちゃあ`
2. 原文 90 字节：`【ミツコ】「正樹君にその気がなくったって、向こうもそうだとは……限らないんじゃない？」`
   显示为前 **57** 字节：`【ミツコ】「正樹君にその気がなくったって、向こうもそうだ`

截断长度正好等于这两句**中文译文的字节数减 1**（中文含结尾 0x01 为 69/58 字节）。

## 根因
`cnpatch.c` 的 `storefix`（v1.18 引入，用于让存档备注以日文写入）在每句绘制后扫描内存，把中文副本还原成日文。它有两个分支：

- **分支1**：`[flags][len][cap][text]` 定容槽（cap=0x80/0x100），容量足够就写完整日文并更新 len。**存档备注读的就是这类槽**。
- **分支2**：`[u16 len][text]` 计数串，容量未知，只写日文前缀（长度=中文长度），其余补空格。

分支2 实际上会命中原句在显示链路里的副本：它把中文按**中文长度**改写成日文前缀，并保留中文结尾的 `0x01`，
于是副本变成「日文前 N 字节 + 0x01 + NUL + 原日文尾部」。回想/回放读取的正是这份副本，所以显示成被截断的日文。

而分支2 对存档备注没有贡献（备注来自分支1 的定容槽），因此可以安全停用。

## 实机证据（运行时地址）
- msglog：回想重放时钩子收到的是**完整日文**（97/90 字节），查找命中并执行了替换。
- 显示期间内存里存在被截断的副本，例如 `0x0381B2B6`：前面 `[u16 69]`，后面日文前 68 字节 + `0x01`——这是分支2 的专属指纹。
- `0x0D32F8A8`（SetText 收到的缓冲）：点击推进前是完整日文 90 字节；推进后变成 `日文前 57 字节 + 0x01 + NUL + 日文尾部`。
- 消息对象 `0x03C8E408`（vtable `0x1009DF88`）的 `+0x68`/`+0x1DC` 两处字符串始终是完整日文（len=0x61/0x5A），
  这是**分支1** 在 SetText 之后把它们从中文洗回日文的结果；它们不参与正文/回味渲染（改成中文画面无变化）。
- 日志：每句 storefix 命中 4 份副本（2 份 cap=0x80 定容槽 + 1~2 份计数串）。

## 修复
- `patch_copy_hit` 的分支2 改由 `config.ini` 的 `storefix2` 控制，**默认 0（停用）**；分支1 保留。
- 新增配置项 `storefix2`（0=不改写计数串，1=旧行为）。
- 另加诊断日志 `COPY p=... len16=... branch=...`（log=1 时输出），便于以后核对命中情况。

## 验证
- 2026-11-21 实机复验（读回存档20 → 重放到回想段）：
  **正文**：`【美津子】「就算你没那个意思，对方也未必……没有吧？」` ✓
  **回味**：`【美津子】「女人啊，小时候约定的之类的，可是会记得清清楚楚的哦？」`、
  `【美津子】「就算你没那个意思，对方也未必……没有吧？」` ✓
- 日志：`branch=2` 计数为 0；显示链路的计数串命中 `branch=0`（不再被改写）。

## 存档备注
分支1 仍在每句之后把 `[flags][len][cap]` 定容槽还原成完整日文（日志里 `COPY ... branch=1`），
因此存档备注机制不受影响。建议下一次存档时在「続きから」界面复核一次备注是否仍为可读日文。

## 后续可做（非必需）
- 全内存扫描仍是每句 15–31ms；以后可改成「只还原 SetText 对象 `this+0x68`/`this+0x1DC` 两处定容槽」的定点版本，省时间且更不易误伤。
