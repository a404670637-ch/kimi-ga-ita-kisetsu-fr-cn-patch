# 跨表一致性总审计（2026-11-20，v1.19.1 数据）

脚本：`work/p5/t_cross_audit.py`（只读）；目的：找出「某张表重建了、另一张没跟上」这类静默回归
（上一轮正是这样抓到选项表 48 条全错的）。

## 结果

| 检查 | 结果 |
| --- | --- |
| 正文表用到的所有双字节码能否解析（隧道表命中 或 原生 cp932 合法） | **未解析 0 处** |
| 选项表用到的所有双字节码 | **未解析 0 处** |

| 正文表 key 是否唯一 | **唯一**（44,138/44,138） |

| 语料 44,139 条在正文表的覆盖 | **缺 1 条**，即 id 44138（纯控制符行，设计上跳过） |
| namemap 条目 | 175 行（对应表内 174 个中文名牌，另有 1 行为生成器同名变体） |
| 选项表解码回译 vs choice.jsonl | **48/48 完全一致**（上一轮已验） |
| namemap ↔ 表内名牌 | **174/174**（此前已验） |

## 结论
v1.19.1 的四张数据（txt / uni / choice / namemap）**互相自洽**，未发现新的「漏重建」痕迹。

## 顺带确认（本轮新实验，均无副作用）
- 收到新台词时**不会**新增 DIB 表面（扫描 BITMAPINFOHEADER：推进前后均 10 个、地址完全一致），
  所以「回味行缓存 = 每行一张 DIB」的假设不成立；
- 当前句在内存里只有 1 份中文（SBO 节点），没有任何带长度前缀的打包副本，
  也没有指向它的指针——这类界面/回想的缓存形式仍需**绘制层钩子**才能看清。
