# 回味/读档「一行日文 / 乱码」根因（2026-11-20 定案）

## 一句话结论
不是渲染 bug。**回味历史与"读档后第一句"都是存档里保存的字节，读档时引擎直接还原、
不经过补丁的替换钩子**，所以存档里存的是什么就显示什么。用 v1.19.1 **重新保存一次**即根治。

## 两种现象与对应成因
| 存档保存时的版本 | 存档里存的内容 | 读档后显示 |
|---|---|---|
| v1.19.1（当前，keepzh=1） | 中文（新隧道码） | 中文 ✅ |
| v1.19 前后至 v1.18（旧隧道码） | 中文（旧编号） | **乱码汉字**（如「蛙咱碳髓鵐拷拷看熄」） |
| 更早的构建（未存中文） | 日文原文 | **日文**（如「【まりか】「えい！」」） |

用户报的那一行日文＝**旧版本存档里保存下来的那一句**（典型是存档时停在屏幕上的那一句，
它同时会出现在回味列表里），所以表现为"回味里只有一两行是日文，其余都是中文"。

## 可复现实验（全程隔离，用户存档 13 个文件 sha256 与备份逐字节一致）
1. 把 `C:\Users\40467\Documents\age\君がいた季節FR\Vmreg` 改名备份，新建空 Vmreg；
2. 新开一局推进 5 句 → 右键 セーブ → 槽位 1：**存档卡片备注是日文**（storefix 设计如此）；
3. 退出进程重启 → 标题「続きから」→ はい：第一句**中文**，回味四行**全中文** ✅；
4. 换成用户 2026-09-02 的旧存档：第一句**日文**、回味旧记录**全为日文**；
5. 换成 2026-11-13 的旧存档（v1.19 重建隧道码之前）：第一句**乱码汉字**、回味同样受影响；
6. 每次实验后 `taskkill /F` → 删除测试 Vmreg → 还原备份 → sha256 全等 ✅。

## 为什么"运行时打补丁"救不了旧存档
- 还原的字符串在内存里有 8~9 份（多为 MEM_PRIVATE 堆，1 份是我们 DLL 的 g_orig）；
- 但**画面用的是已经解析好的字形结构**：把内存里的字符串改成中文后再强制重绘，
  屏幕上的那一句**不变**（已实测）；
- 回味里的旧记录更彻底：连原始字符串都搜不到（按整串、按尾部子串、SJIS 三种方式，
  0 命中）——说明在载入时就被解析成字形序列并释放了。
→ 只能改写存档数据本身或钩住载入解析路径（较大逆向工程），现实解法就是重新保存。
